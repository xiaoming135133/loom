## 每周仪式（三人各十分钟）

1. **周一**：从 [`03-项目计划.md` §3.2](03-项目计划.md) 把本周任务拆成 Issue，每条写清验收标准，指派到人。
2. **每天**：只认一条规则——**当天必须有一条 PR 合进 main**，哪怕只是把某段文档改准。
3. **周五**：半小时碰头，做三件事：更新本文件的勾选表、打一个 tag、把没做完的任务写明原因（不是「下周继续」，而是「因为 X，改成 Y」）。

## 风险触发器（到点就动手，别等）

| 触发条件 | 立刻做的动作 |
| --- | --- |
| W2–W3 末 baseline 公式可用率 < 50% | 换识别服务；或首版只做「公式区保留截图 + 手写修正」，把「可改」而不是「认得准」做成卖点 |
| W4 末对齐准确率 < 60% | 四选一降为两选一（挂载 / 待定），先保证不污染树；新建与扩展改手动 |
| W6 末检索连一版都跑不出 | 砍到「关键词 + 章节过滤」两层，符号层演示用固定样例 |
| 任一周延期 > 2 天 | 按下面的顺序砍范围，并在周五会上明确说出来 |
| 距 W9 还剩 3 周而主链路未闭环 | 冻结新功能，只做「拍 → 对齐 → 改 → 检索」四步的稳定性 |

## 砍范围顺序（从下往上砍）

1. 平板手写批注（本来就用网页端替代）
2. 关系图跨课程自动合并（只读展示保留）
3. 复习算法精细化（先用固定间隔）
4. 题目五槽位 → 三槽位（题干、知识点、卡点）
5. 网页整理台 → 纯只读视图
6. **绝不砍**：拍 → 识别 → 对齐 → 修改 → 检索 主链路，以及「原图永远可对照」
